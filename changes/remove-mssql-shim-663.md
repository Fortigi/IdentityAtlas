- Fixed: deleting a governance category (Admin → Categories) failed with an internal error against PostgreSQL; it now deletes correctly.
- Internal: removed the legacy SQL-Server compatibility shim entirely — every API endpoint (including the matrix grid, scope stats/timeseries, roll-ups, inherited-access folds, the permissions grid and the nested-group expand) now issues native PostgreSQL queries with positional parameters. The shim and its `@name`→`$N` rewriter are deleted, and a build guard prevents the shim or a second database pool from being reintroduced. No other user-facing behaviour change.
- The Risk Scoring page's "not yet computed" notice now points you to **Admin → Risk Scoring** to run scoring, replacing an outdated SQL-Server-era PowerShell command.
- Documentation: the data-model, governance, and risk-scoring reference pages now describe the schema with PostgreSQL types (e.g. `TEXT`, `TIMESTAMPTZ`, `BOOLEAN`, `UUID`, `JSONB`) instead of leftover SQL-Server types.

- CSV import now turns nested groups into real access: anyone who holds a resource **through** another one (at any depth) appears on it as an `Indirect` member, exactly as with an Entra ID import. Use `RelationshipType = GrantsAccessTo` in `ResourceRelationships.csv`, where the parent is the resource held and the child is the resource its holders gain — for an Active Directory export, parent = the member group, child = the containing group.
- Inherited members are recomputed on every import: someone who holds a resource both directly and by inheritance is listed once (as `Direct`), eligible-only holders are not propagated, and cycles or diamonds in the nesting never double-count. Removing the nesting from the next import removes the inherited rows with it.
- Works for any CSV source and any resource type (Active Directory and LDAP groups, SAP composite roles), not just groups — and costs nothing for an export that has no nesting rows.
- Fixed: a relationship row removed from `ResourceRelationships.csv` could stay behind. Each relationship type is now reconciled on its own, so dropping a `GrantsAccessTo` row removes it instead of leaving it in place — including the last row of a type: re-importing the file with no `GrantsAccessTo` rows left now removes all of them, for every system the file covers. A missing file, or one with no usable rows, still deletes nothing.
- `Indirect` rows you list yourself in `Assignments.csv` are kept alongside the computed ones, and a row you drop from the file is now removed on the next import instead of staying behind.

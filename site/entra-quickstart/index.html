Entra ID quickstart · for Entra ID Governance admins

Design access packages on facts, not guesswork.

You've switched on Entra ID Governance. Access packages, policies, reviews — ready to go. But which groups belong in which package, and who should get it? Identity Atlas reads your tenant and shows who holds what: governed by a package, or handed out by hand. This page is the shortest route from zero to that insight — about an afternoon, with a link to the guide for every step.

What you get

The insight Entra ID Governance doesn't give you.

Identity Atlas syncs users, groups, roles, apps and the access packages you already have into one model, and shows them in an access matrix: people across, resources down, one cell per membership. Two lenses on that matrix answer the access-package question directly.

See what a package already governs

Build a matrix for one department and switch to the Governed lens. Every coloured cell is access an access package grants — the colour matches the package's column, so you see at a glance which package covers what.

Find access handed out by hand

Switch to Non-governed and what's left is every membership no package governs — the groups people were simply added to. That list is your next access package, with the people who should get it already in the columns.

Agree on the design before you build it

Share the matrix with the resource owner or the team lead. They sign in with their Microsoft account — no Identity Atlas role needed — and see it read-only. Settle the design together, then create the package in Entra.

From zero to insight

Five steps. About an afternoon.

Each step links to the guide that explains it in full. The times are what they take once your prerequisites are in place.

1

Deploy to Azure ~15 min · one click

The Deploy to Azure button installs Identity Atlas into your own subscription with managed platform services (App Service, PostgreSQL Flexible Server, Key Vault). The form only asks for a subscription, a resource group, a region and a size — xs is the proof-of-concept size, from about €45 a month. Entra sign-in is enforced from the first minute; nothing is reachable anonymously.

  • You need Owner on the subscription and Application Administrator in the directory (see the prerequisites in the walkthrough).
  • Prefer containers you run yourself? The Docker stack is the same product — see the Quick Start.
Deploy to Azure ↗ Azure Deployment Walkthrough ↗ Azure Deployment Reference ↗ Docker Quick Start ↗
2

Register the Entra app and switch on sign-in ~5 min · portal

Create one App Registration in your tenant: the deployed URL as the SPA redirect URI, and one exposed API scope named access. Paste the tenant ID and client ID into the Web App's environment variables and it restarts with Entra SSO on. The "Entra ID setup required" page on your fresh deployment walks you through exactly these clicks, and the Authentication guide covers roles and recovering from a lockout.

Authentication & SSO ↗ Walkthrough · Step 2 ↗
3

Add the Microsoft Graph crawler ~10 min · then it syncs

In Identity Atlas go to Admin → Crawlers → Add Crawler and pick Microsoft Graph. Give it a second App Registration (tenant ID, client ID, client secret) with application permissions to read users, groups, directory roles, applications and entitlement management. The wizard validates the credentials and shows which permissions are granted before you continue; tick Identity Governance so your access packages, assignments and policies come along.

Syncing from Entra ID ↗ Required Graph API permissions ↗ Which toggles to enable ↗
4

Build your first matrix ~5 min

Open Matrix → New matrix. Pick the people — one department is a good first scope — choose Resources and business roles so each access package gets its own foldable row, and show it. Then switch between Governed and Non-governed. The first 15 minutes guide takes you through reading one cell properly and comparing intent with reality.

Your first 15 minutes ↗ Reading the Matrix ↗ The words you need first ↗
5

Share it ~1 min

In the matrix wizard's Save & share step, name the matrix and add the colleagues who should see it. They open the link, sign in with their normal Microsoft account and see exactly this matrix, read-only — no Identity Atlas role required. Use it to agree on the package with the resource owner, then build it in Entra.
